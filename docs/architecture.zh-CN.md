# 架构约定

[English](architecture.md)

## 目标与读者

本文面向歌单迁移工具的维护者。迁移成功意味着：保留源歌单顺序；每个源条目都有可审查
结果；只有高置信度匹配可以自动写入；修改 Spotify 前必须获得用户明确确认。

## 系统边界

```text
本地 SPA / 独立 CLI -> 网易云只读适配器 -> 源数据模型
                     -> SQLite 任务/检查点 + Spotify 搜索缓存
                     -> 分级搜索 -> 确定性 Matcher
                     -> 带校验和的不可变计划 + CSV + 手动 CSV
明确执行操作         -> 已验证计划 -> 执行日志
                     -> Spotify 歌单写入器 -> 可恢复批次
```

- `netease.py` 读取网易云公开元数据并校验数量和必需字段。它既支持公开网页使用的只读
  接口，也支持用户自己运行的 `api-enhanced` 兼容服务；两种方式共用相同的完整性校验和
  领域模型。
- `spotify.py` 负责 PKCE 授权、令牌刷新、HTTP 重试、搜索和歌单写入。
- `matching.py` 包含无网络依赖的确定性匹配算法。
- `jobs.py` 管理规划检查点和当前迁移任务的搜索缓存。
- `plans.py` 统一负责计划序列化、完整性验证、报告和手动添加名单。
- `execution.py` 管理外部写入日志、批次恢复和不确定状态协调。
- `migration.py` 编排分级搜索，不隐藏配额或源数据错误。
- `cli.py` 处理输入和面向人的输出，不包含业务算法。安装后的命令入口和
  `python -m cloud_playlist_bridge` 都能直接运行 `plan` 和 `apply`，无需启动网页 App。
- `app.py` 是只监听回环地址的 HTTP 编排层。它在后台线程调用相同服务，并向 SPA 提供
  增量状态。
- `web/` 是不依赖外部资源的 SPA。歌曲列表使用窗口化渲染，避免为大歌单中的每首歌曲
  同时创建 DOM 节点。
- `launchers.py` 生成调用同一个 Python 模块和浏览器界面的平台启动器。启动器状态写入
  当前用户的应用数据目录。
- 应用是普通 Python 程序，不需要 Agent、插件或 Codex 运行时。

## 数据流与不变量

1. 从输入中解析纯数字歌单 ID。
2. 获取歌单详情。完整源顺序由 `trackIds` 决定，不能使用可能被截断的 `tracks` 列表。
3. 分批获取歌曲详情，以 ID 建立索引，再恢复 `trackIds` 顺序。
4. `trackCount`、`trackIds` 和 `--expected-count` 发生冲突时停止。歌曲详情缺失时默认停止
   规划，只有用户明确允许残缺迁移后才能继续。
5. 逐首把搜索和匹配结果提交到任务数据库。只有源快照相同时才允许恢复任务。
6. 先执行精确查询；达到自动匹配要求时提前结束，否则执行后备查询。相同查询复用缓存。
7. 完整计划必须包含 schema 版本、计划 ID、源摘要、策略设置和 SHA-256 完整性校验。
   `apply` 只接受有效计划，且不会重新搜索。
8. 只按源顺序写入 `matched` URI。每个跳过条目、拒绝原因和最多三个候选链接都写入
   `manual.csv`。
9. 每次 Spotify 请求最多写入 100 首歌曲。发送前记录 inflight 批次，确认后保存完成数量
   和 snapshot ID；恢复前必须先协调状态不确定的批次。

## 匹配约定

匹配器执行 Unicode NFKC、大小写折叠以及空白和标点归一化，并把常见版本标记识别为
完整单词或明确中文标签。评分由标题、完整歌手集合、时长和专辑组成。自动匹配必须同时
满足最低总分、最低标题分和歧义差距，否则结果为 `low_confidence` 或 `ambiguous`。
算法不使用机器学习，也不使用 Spotify 内容训练模型。

## 安全与隐私

- 桌面客户端使用 Authorization Code with PKCE，绝不请求 Client Secret。
- OAuth 权限仅包括公开和私有歌单修改，以及恢复私有歌单所需的读取权限。
- 校验 OAuth state，回调只监听明确的回环地址。
- 在平台允许时把令牌文件权限限制为当前用户，并始终排除在版本控制之外。
- 日志和报告中不得写入 access token、refresh token 或网易云 Cookie。
- App 默认绑定 `127.0.0.1`，所有状态变更请求都必须携带进程生成的 CSRF token。
  Spotify 令牌不得进入浏览器状态或日志。
- 只有用户明确配置时才接受 `api-enhanced` 服务。第三方服务的安装、更新和 Cookie 管理
  由用户负责。

## 失败语义

- 输入无效：退出码 2，不产生外部写入。
- 网络、字段、鉴权或速率额度耗尽：退出码 1，并说明失败阶段。
- 配额耗尽后保留可恢复的规划进度。
- 匹配不到是结果而不是程序错误：写入报告并继续；没有任何匹配时拒绝执行计划。
- Spotify 歌单创建后失败：执行日志状态为 `partial` 或 `uncertain`。再次运行 `apply`
  时先协调再恢复；无法安全确定远端状态时停止并说明恢复条件。

## 维护者验证

在仓库根目录运行离线检查：

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 -m compileall -q src tests
```

维护范围包括 URL 和 ID 解析、源顺序恢复、匹配与歧义拒绝、带缓存和恢复能力的规划、
计划完整性、分批写入与恢复、报告生成、回环与 CSRF 边界，以及启动器生成。新增行为必须
添加或更新对应测试，不得把真实账户数据或生成的迁移报告带入仓库。
